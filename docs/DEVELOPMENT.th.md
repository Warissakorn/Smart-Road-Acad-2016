# แนวทางพัฒนา Smart Road สำหรับ AutoCAD 2016

เอกสารนี้อธิบายการพัฒนา Smart Road สำหรับ AutoCAD 2016 รุ่นเต็มบน Windows เป้าหมายคือช่วยช่างเขียนแบบทำงานตั้งแต่รับแนวถนนจนถึงส่งแปลน โดยลดทั้งเวลาวาดครั้งแรกและเวลาที่ต้องแก้แบบเมื่อแนวหรือหน้าตัดเปลี่ยน

## เริ่มจากงานที่ผู้ใช้ต้องส่ง

หลังรับรองการตั้งหน่วยของ Smart Road และเส้นตีแบบ Linetype บน AutoCAD 2016 แล้ว งานถัดไปที่เสนอคือ **ป้ายรถเมล์พร้อมช่องจอดบนแนวถนนเดิม** เพราะใช้ทดสอบการทำงานร่วมกันของถนน ทางเท้า และขนส่งสาธารณะได้ในงานเดียว ปัจจุบันผู้ใช้แก้หน้าตัดด้วย `SRSECTION` และวางสัญลักษณ์ป้ายด้วย `SRTRANSIT` แยกกัน จุดที่ควรลดคือการระบุตำแหน่งซ้ำและการขยับสัญลักษณ์ตามหลังแก้แนว

| ลำดับที่เสนอ | สิ่งที่จะส่งมอบ | วิธีพัฒนาและเงื่อนไขรับงาน |
|---|---|---|
| 1. ป้ายรถเมล์และช่องจอด | เลือกแนว ฝั่ง และช่วงครั้งเดียว ได้ช่องจอด ทางเท้า และตำแหน่งป้าย | ใช้หน้าตัดและ taper เดิม ผูกป้ายกับแนวและระยะตามแนว เมื่อแก้ตำแหน่งแล้วสร้างซ้ำต้องเหลือป้ายเดียว กด Undo ครั้งเดียวต้องย้อนทั้งชุด |
| 2. ทางแยกและทางข้าม | ปิดขอบผิวทาง เชื่อมทางเท้า และหยุดเส้นตีที่ทางข้ามหรือเขตทางแยก | ขยายจากการตัดขอบทีละคู่ใน `SRCONNECT` ให้เก็บแนวที่ร่วมทางแยก จุดตัด และช่วงที่ได้รับผล เริ่มจากสามแยกระดับเดียว ทดสอบว่าสีพื้นไม่ซ้อนและการแก้แขนทางหนึ่งรักษางานบนแขนอื่น |
| 3. งานระดับและรูปตัด | รูปตัดตามสถานี แสดงระดับเดิม ระดับออกแบบ และความลาดขวาง | เริ่มเมื่อมีข้อมูลสำรวจ จุดอ้างอิงระดับ และนิยามสถานีที่ตกลงกับผู้ออกแบบ เก็บข้อมูลระดับแยกจากแปลน 2D และตรวจรูปตัดกับตัวอย่างที่วิศวกรคำนวณไว้ |

ให้จับเวลางานตัวอย่างเดียวกันสองรอบด้วย AutoCAD ปกติและด้วยปลั๊กอิน วัดตั้งแต่เปิดแบบจนได้แบบส่งมอบ รวมการเปลี่ยนแนวหนึ่งครั้ง บันทึกเวลารวม จำนวนจุดที่ต้องแก้มือ และข้อผิดพลาดที่ยังค้าง คำนวณร้อยละเวลาที่ลดได้ด้วย `100 × (เวลาวิธีเดิม − เวลาที่ใช้ปลั๊กอิน) / เวลาวิธีเดิม` ถ้าผลติดลบ ให้กลับไปแก้ขั้นตอนที่เพิ่มภาระก่อนขยายเครื่องมือ

| การติดตั้งและปล่อยรุ่น | `installer/SmartRoad.iss`, `.github/actions/build-installer/action.yml`, `.github/workflows/` | Inno Setup ติดตั้งต่อผู้ใช้ ส่วน GitHub Actions สร้าง EXE และ ZIP ตรวจการติดตั้งทับ และเผยแพร่เมื่อ `main` มีเวอร์ชันที่ยังไม่มีแท็ก หรือเมื่อ push แท็กที่ตรงกับ manifest |

### รูปแบบข้อมูลใน DWG

แนวอ้างอิงเป็น LINE, ARC หรือ LWPOLYLINE เปิดใน Model Space บนระนาบ XY ของ WCS ซ้ายและขวาอ้างตามทิศจากต้นแนวไปปลายแนว ระยะสถานีในแบบจำลองคือระยะสะสมจากต้นแนวในหน่วย DWG ตัวอย่างต่อไปนี้เป็นค่าที่ส่งให้ฟังก์ชันเมื่อแบบใช้เมตร

```lisp
;; Base section and one station override, in metres
'(
  ((("Lane" 3.5)) (("Lane" 3.5) ("Walkway" 2.0)))
  ((20.0 50.0
    ((("Lane" 3.5)) (("Lane" 3.5) ("Bus" 3.0) ("Walkway" 2.0)))
    5.0))
)
```

รายการแรกคือหน้าตัดหลัก เรียงองค์ประกอบแต่ละฝั่งจากแนวอ้างอิงออกไป รายการที่สองคือช่วงแก้ไข แต่ละช่วงเก็บระยะเริ่ม ระยะจบ หน้าตัดใหม่ และระยะ taper ต่อปลาย ในตัวอย่างนี้ `sr:spans` แบ่งช่วง 20–25 ม. สำหรับขยายหน้าตัด ช่วง 25–45 ม. สำหรับความกว้างเต็ม และช่วง 45–50 ม. สำหรับคืนสู่หน้าตัดหลัก

| ชื่อแอป XData | วัตถุที่เก็บ | สิ่งที่ผู้พัฒนาต้องรักษา |
|---|---|---|
| `SR-CORRIDOR` | แนวอ้างอิง | `sr:save-model` เขียนโมเดลเป็นข้อความ DXF 1000 ครั้งละไม่เกิน 240 อักขระ อ่านกลับด้วย `sr:model` แล้วตรวจด้วย `sr:model-valid-p` ก่อนใช้งาน |
| `SR-CORRIDOR-EDGE` | ขอบที่ปลั๊กอินสร้าง | DXF 1005 อ้าง handle แนวต้นทาง ส่วน 1000 เป็นลายเซ็นเรขาคณิตของแนว และ 1040 สองค่าระบุช่วงสถานี ใช้ `sr:span-inventory` ตรวจว่าขอบครบและเป็นของแนวรุ่นที่กำลังแก้ |
| `SR-ROAD-STYLE` | พื้นสีและเส้นตีของ Corridor | เก็บเจ้าของ รูปแบบสี และช่วงสถานี เวลาสร้างซ้ำให้แทนงานสีของช่วงที่เกี่ยวข้อง และกรองวัตถุกลุ่มนี้ออกจากการเลือกแนวใน Quick Build |
| `SR-JUNCTION-EDIT` | ขอบ Corridor ที่ตัดด้วยเครื่องมือเชื่อมทางแยก | รุ่น 2 ของข้อมูลเก็บช่วงสถานีที่เว้นงานสีเป็นคู่ DXF 1040 รุ่นเดิมเว้นทั้งช่วงที่แก้ Rebuild ให้ยืนยันก่อนแทนที่ขอบดังกล่าว |
| `SR-TRANSIT-ANCHOR` | สัญลักษณ์ป้ายหยุดรถและชานชาลาที่เลือกผูก | เก็บ handle แนว DXF 1005 ชนิดสัญลักษณ์ DXF 1000 และสถานี ฝั่ง ระยะร่น ความยาว และความกว้างด้วย DXF 1040 สร้างสัญลักษณ์ใหม่พร้อมการแก้ Corridor ใน Undo ชุดเดียว |

หน่วยพิกัดและหน่วยกรอกของ Smart Road บันทึกใน DWG ผ่าน `SRSETTINGS` ใช้ `sr:unit-scale` เพื่อแปลงเมตรเป็นหน่วยพิกัด และใช้ `sr:number` สำหรับถามความยาวในหน่วยกรอกแล้วคืนค่าเป็นหน่วยพิกัด ค่ามาตรฐานและขนาดลายเส้นจราจรเก็บเป็นเมตร ส่วนพิกัดและช่วงสถานีใน Corridor ยังเก็บเป็นหน่วยพิกัดของ DWG การเปลี่ยนหน่วยกรอกจึงรักษาขนาดแบบเดิม

แยกแม่แบบส่วนตัวออกจากข้อมูลโครงการ หน้าตัดของถนนจริงอยู่ใน DWG ส่วน Quick Build และแม่แบบชื่อใช้โปรไฟล์ AutoCAD ผ่าน `sr:pack-profile` และ `sr:unpack-profile` แม่แบบใหม่เก็บความกว้างเป็นเมตรเพื่อใช้ข้ามแบบ แม่แบบเก่าที่มีตัวคูณหน่วยในข้อมูลใช้ตัวคูณนั้น ส่วนแม่แบบชื่อเก่าที่ไม่มีข้อมูลหน่วยต้องระบุหน่วยต้นทางเมื่อโหลด

เส้นตีประใช้ Linetype บน Polyline ที่ครอบคลุมตลอดแนวต่อเนื่องของเส้นตีหนึ่งแนว พร้อมเปิดการสร้างลายต่อเนื่องที่จุดยอด ช่วงสถานีที่เว้นงานสีแบ่งแนวเป็นคนละ Polyline เก็บช่วงสถานีของ Polyline ทั้งแนวใน `SR-ROAD-STYLE` เพื่อให้การตัดขอบและ Rebuild ระบุงานสีที่ต้องสร้างซ้ำได้

## ตัวอย่างการพัฒนาคำสั่งป้ายรถเมล์พร้อมช่องจอด

ชื่อ `SRBUSSTOP` ในส่วนนี้เป็นชื่อคำสั่งที่เสนอสำหรับงานระยะที่ 1 ทีมสามารถเริ่มทดสอบด้วยการพิมพ์ชื่อคำสั่งก่อนเพิ่มปุ่มบน Ribbon

1. **รับข้อมูล** เลือกแนว Corridor แล้วเรียก `sr:model` และ `sr:model-valid-p` ให้ผู้ใช้เลือกฝั่งและคลิกต้น–ปลายช่วงตามแบบอย่าง `sr:pick-range` แปลงจุดจาก UCS เป็น WCS ก่อนฉายลงแนว เก็บระยะตามเส้นโค้งจริงเพื่อให้ช่วงช่องจอดบนโค้งยาวตามทางวิ่ง
2. **สร้างโมเดลในหน่วยความจำ** เพิ่มแถบ `Bus` ไว้ระหว่างช่องวิ่งกับทางเท้าของฝั่งที่เลือก รักษาลำดับองค์ประกอบเดิมและหน้าตัดอีกฝั่ง ตรวจช่วงซ้อน ความกว้าง และระยะ taper แสดงสถานีและความกว้างสุดท้ายให้ตรวจใน Preview ก่อนเขียน DWG
3. **สร้างเรขาคณิต** ใช้ `sr:spans` และ `sr:span-safe-p` ตรวจช่วงที่จะเปลี่ยน แนว ARC ที่ offset คงที่ใช้ ARC จริง ส่วน taper ใช้จุดตัวอย่างตามความโค้ง ตรวจขอบพับกลับหรือข้ามกันเมื่อช่องจอดอยู่ใกล้จุดหักหรือโค้งรัศมีแคบ วางป้ายโดยอิงจุดและทิศสัมผัสของแนวที่สถานีที่เลือก
4. **ผูกป้ายกับถนน** เสนอให้เก็บเวอร์ชันข้อมูล, handle แนวต้นทาง, ฝั่ง, สถานี และระยะเยื้องของป้ายใน XData เฉพาะงานป้าย เพื่อค้นหาป้ายเดิมเมื่อย้ายหรือสร้างซ้ำ หากตัดแนวจนสถานีป้ายอยู่นอกช่วง ให้แสดงตำแหน่งที่ต้องแก้ก่อนยืนยัน
5. **เขียนและย้อนการแก้** ใช้ `sr:replace-section` และ `sr:apply-spans` เป็นแบบอย่างการหาช่วงที่เปลี่ยนและการคืนข้อมูล ออกแบบให้การแก้ขอบ สี และป้ายอยู่ใน undo mark เดียว บันทึกรายการวัตถุใหม่ วัตถุเดิมที่ลบ และ XData ก่อนแก้ หากสร้างป้ายล้มเหลวหลังสร้างขอบ ต้องคืนทั้งหน้าตัดและขอบเดิมด้วย

## การเพิ่มคำสั่งลง Ribbon และสร้าง Bundle

คำสั่งวาดใหม่และสร้างจากแนวเดิมเรียก `sr:create-road` ร่วมกัน ส่วน `SREDIT`, `SRSECTION` และ `SRSTYLE` ใช้ `sr:pick-corridor` ร่วมกันเพื่อตามกลับไปหาแนวอ้างอิงจากวัตถุที่เลือก

แก้ไฟล์ต้นฉบับที่ราก repository ระหว่างพัฒนา ใช้ `APPLOAD` โหลด LSP แล้วทดสอบคำสั่งกับสำเนา DWG บน AutoCAD 2016 สำหรับปุ่มใหม่ให้เพิ่มรายการใน `sr:toolbar-spec` เพิ่มคำสั่งใน `PANELS` และเตรียม BMP ขนาด 16×16 กับ 32×32 ตามชื่อที่รายการปุ่มอ้างถึง ตรวจว่าปุ่มเดิมถูกแทนที่บน Toolbar ของเครื่องที่ติดตั้งรุ่นก่อน

จากราก repository ใช้ PowerShell ทำให้ไฟล์ที่ติดตั้งตรงกับต้นฉบับ แล้วสร้างและตรวจ Ribbon

```powershell
Copy-Item -LiteralPath 'Smart Road.lsp' -Destination 'SmartRoad.bundle/Contents/Smart Road.lsp' -Force
python tools/build_ribbon.py
python tools/build_ribbon.py --check
```

สำหรับการทดสอบการโหลดอัตโนมัติ ให้ปิด AutoCAD คัดลอก Bundle ไปที่ `%APPDATA%\Autodesk\ApplicationPlugins` แล้วเปิดใหม่ ทดสอบคำสั่งเดียวกันทั้งจาก command line และปุ่มบน Ribbon เมื่อเตรียมออกรุ่น ให้ตั้ง `AppVersion` และ `ComponentEntry.Version` ทุกตัวใน manifest ให้ตรงกัน การ merge เข้า `main` เรียก workflow Build และจะเผยแพร่ EXE กับ ZIP อัตโนมัติเมื่อ `AppVersion` ยังไม่มีแท็ก ให้บันทึกผลทดสอบบน AutoCAD 2016 ก่อน merge การเพิ่มรุ่น การ push แท็ก `vX.Y.Z` ที่ตรงกับ manifest ยังเรียก workflow Release ได้เช่นกัน
